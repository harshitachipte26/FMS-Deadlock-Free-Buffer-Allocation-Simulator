FMS Deadlock-Free Buffer Space Allocation Simulator

In an automated Flexible Manufacturing System (FMS), workpieces follow strictly ordered machining routes through workstations with finite-capacity buffers. When buffers fill up, upstream machines become blocked. Interacting resource contentions create catastrophic circular wait deadlocks that halt entire factories.

This simulator implements Dijkstra's Banker's Algorithm adapted as a real-time buffer-space allocation supervisor. By exploiting deterministic part routing, the controller evaluates tentative future states and delays unsafe transitions, guaranteeing deadlock-free manufacturing.

OS vs. FMS Banker's Formulation
  • Resources: Discrete buffer slots ($B_1, B_2, B_3$) and machine bays.
  • Route Claims: Part routes provide deterministic a priori maximum claims.
  • Pipelined Release: Resources are held and freed stage-by-stage as workpieces advance.
  • Deadlock Avoidance: Proactive online controller; does not merely detect deadlocks after they happen.

Banker's Safety Algorithm Rules in Manufacturing:
  1. Condition 1 (Adherence to Route Claim): Request ≤ Need. The part cannot claim a buffer that does not appear in its remaining route.
  2. Condition 2 (Capacity Constraint): Request ≤ Available. The destination buffer must have at least one free physical slot.
  3. Condition 3 (Safe Future State): Tentatively assign Available' = Available − Request, Alloc' = Alloc + Request, Need' = Need − Request. Search for a completion sequence where each remaining workpiece satisfies Need' ≤ Work. If found, the move is GRANTED. If not, the move is DELAYED to avoid circular wait deadlock.

Authors: Mark A. Lawley, Spyros A. Reveliotis, and Placid M. Ferreira
Journal: International Journal of Flexible Manufacturing Systems, Vol. 10, pp. 73–100 (1998)
DOI: 10.1023/A:1007969601583

Research Motivation & Context

In modern Flexible Manufacturing Systems (FMS), workstations and automated guided vehicles (AGVs) process diverse parts concurrently. Because physical intermediate buffer storage is limited by floor space, machine tools, and tooling racks, finite-capacity buffers frequently become bottlenecks.

When a machine finishes machining a part, it cannot release the part until downstream buffer space is secured. If two or more parts with cross-flowing routes hold buffer spaces while waiting for buffers held by each other, a circular wait deadlock occurs. In manufacturing, aborting a part means scrapping expensive material or risking machine collision. Deadlock avoidance is therefore critical.

Why Banker's Algorithm Fits Manufacturing

Dijkstra’s Banker’s Algorithm is fundamentally based on knowing the maximum claim of each process before execution. In general-purpose Operating Systems, programs rarely know their future resource requests ahead of time. In an FMS, however, part routes and processing sequences are deterministic and known in advance.

Lawley, Reveliotis, and Ferreira (1998) realized this natural congruence and formulated Banker's Algorithm as an online supervisor for buffer-space allocation, testing tentative states prior to granting part movements.

Educational Model Formulation & Assumptions

Implemented Simulator Model:
  • Resources: Buffer spaces $B_1, B_2, B_3$ with configurable capacities ($C_1, C_2, C_3$).
  • Workstations: 3 CNC machines with discrete operation times.
  • Part Routing: 3 part types with cross-flow routing (Part A: M1→B2→M2; Part B: M2→B1→M1; Part C: M3→B1→M1).
  • Stage-by-Stage Transfer: Workpieces release upstream buffer slots when entering a machine, holding only current resources.
  • Supervisor Logic: Exact implementation of Lawley et al.'s safety check with Work and Finish vectors.

Limitations & Future Scope

This simulator models an educational abstraction of Lawley et al.'s framework. The paper also explored alternative routings (routing flexibility), polynomial vs. NP-complete deadlock avoidance policies (DAPs), and automated AGV transport. Future simulator extensions could incorporate stochastic machine breakdowns, tool wear, and automated fixture pallet constraints.

Banker's Resource-Request Algorithm

Simulate a process requesting additional resources, verified against Banker's 3 conditions.

Remaining Need: —
Must satisfy: Request ≤ Need and Request ≤ Available.
Banker's Algorithm Request Rules:
  1. If Request[i] ≤ Need[i]: Proceed to step 2. Otherwise, throw an error (process exceeded maximum claim).
  2. If Request[i] ≤ Available: Proceed to step 3. Otherwise, process must wait (resources unavailable).
  3. Tentatively allocate: Available = Available − Request, Alloc = Alloc + Request, Need = Need − Request. If resulting state is safe, request is granted!

Banker's Logic

1
Calculate Need

For each process, Need[i] = Max[i] − Allocation[i].

2
Evaluate Eligibility

Find an unfinished process where Need[i] ≤ Work for all resources.

3
Release Resources

Simulate execution: Work = Work + Allocation[i], mark Finish[i] = true.

4
Safety Decision

If all processes finish, state is SAFE. Otherwise UNSAFE.

SAFETY CONDITION
Need[i][j] ≤ Work[j] (∀ j)
